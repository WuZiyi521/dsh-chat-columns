# 宿主契约审计（DSH Web 0.2.1-alpha.2）

只读审计：从宿主已安装的 bundle 里逐条核对插件依赖的 DOM 契约。
审计对象（静态源码，不是运行时探测）：

```
<DSH 安装目录>\node_modules\@deepseek-ai\dsh\node_modules\@deepseek-ai\
  dsh-client-ui-chat\lib\client.js
  dsh-client-ui-conversation\lib\client.js
  dsh-client-ui-renderer\lib\client.js
```

（本机实测版本：`0.2.1-alpha.2`。Windows 上 `<DSH 安装目录>` 通常是
`%USERPROFILE%\.dsh-win\versions\<版本>`。）

> 结论先行：插件只依赖下面 8 个「数据属性级」契约，**不依赖任何哈希 class**（宿主 class 形如 `EvIC1a_column`，会随构建变化）。

---

## 1. 会话结构与选择器

| 契约 | 宿主证据 | 插件用途 |
|---|---|---|
| `[data-conversation-scroll]` 是唯一滚动容器 | `ConversationRoot`: `div.scrollBody[data-conversation-scroll]`，CSS `overflow-y:auto` | 主滚动容器、滚动量 s 的来源 |
| `[data-conversation-session]` 在滚动容器的祖先上 | `div.body[data-conversation-content][data-conversation-session=sessionId]` | 会话切换检测（2.0 用的 `scroller.querySelector` 在这里查不到，已改成 `closest`） |
| `[data-composer-seat]` 在滚动容器**内部** | `composerSeat` 是 scrollBody 的子节点，CSS `position:sticky; bottom:0` | 阅读视口 = 滚动容器顶 → 输入区顶 |
| `[data-chat-flow]` 是正文列 | `div[data-chat-flow]` + `className=ChatView_module.column`，CSS `max-width:var(--dsh-chat-content-width); display:flex` | A 的多列容器 / B 的粘滞视口层 |
| `[data-chat-flow-key]` 是消息行 | `div.flowItem[data-chat-flow-key][data-chat-flow-kind][data-chat-turn]` | 消息识别与稳定 ID |
| `[data-chat-group-key]` 是分组卡片（行内的嵌套 flow） | `ChatGroupSeat`: `div[data-chat-group-key][data-chat-flow-key]`，内部还有 `div[data-chat-flow]` | 排除嵌套行，把分组当成一条消息 |
| 插槽层是 `display:contents` | renderer `SlotOutlet`: `<div data-slot=... style={display:"contents"}>` | 消息行在布局上等价于正文列的直接子节点（CSS 多列/绝对定位都能生效） |
| 宿主「加载更早」是列内的按钮 | `hasMore && <div className=older><button disabled={loadingOlder} onClick={loadEarlier}>` | 历史加载只点它 |

## 2. 宽度变量

```css
/* ConversationRoot 的 body */
--dsh-chat-content-width: var(--dsh-chat-user-width, clamp(680px, calc(var(--dsh-conversation-column-width,0px) * .64), 920px));
```

- 正文列 `max-width: var(--dsh-chat-content-width)`，默认上限 920px。
- 920px 摊成 3 列每列只剩约 280px，所以在 A/B 多列时把它放到 `100%`（写在**列自己**的内联样式上，不影响输入框宽度）。
- 写的是自定义属性，快照/恢复用的是 `style.getPropertyValue`，退出时原样还回。

## 3. 输入区与阅读视口

```css
.composerSeat { position: sticky; bottom: 0; z-index: 7 }
```
- 输入区是**吸底**的，但仍在滚动内容里：`scrollHeight` 含输入区高度。
- 因此：`H = composerTop - scrollportTop`，且 `maxScroll = scrollHeight - clientHeight` 正好等于 `占位层高度`（因为占位层 = 逻辑总高 - H）。
- B 的列高必须精确等于 H，所以插件把正文祖先的 16px 上下内边距归零（快照可还原）。

## 4. 宿主自己的滚动/锚点机制（不能抢）

| 机制 | 证据 | 插件策略 |
|---|---|---|
| 浏览器滚动锚定 | `[data-conversation-scroll]:has(.root[data-chat-following-tail]) { overflow-anchor: none }` | B 期间也写 `overflow-anchor:none`，由插件自己换算位置 |
| 宿主锚点补偿 | `ChatViewport` 用 `data-chat-paging-anchor` 行 + `getBoundingClientRect().top` 差值补 `scrollTop`（`beginPaging` / retain） | 插件在 A/C 不写 `scrollTop`；B 写，但只在模式进入/重排时写一次，且用消息 ID + 列内偏移换算 |
| 「跟随最新」 | `[data-chat-following-tail]` 在 ChatView root 上 | 切换模式时如果正在跟随，保持在末尾 |
| 滚到顶自动加载 | 宿主**没有**，只有 `.older > button` | 插件自己判断「用户在顶部」后点宿主按钮 |

## 5. 主题

| 信号 | 证据 | 用法 |
|---|---|---|
| `body[data-ds-dark-theme]` | 宿主深色主题标记 | 第一优先级 |
| `html[data-ds-theme-source="dark|light"]` | 主题来源 | 第二优先级 |
| `getComputedStyle(html).colorScheme` | — | 第三优先级 |
| `body` 背景亮度 / `prefers-color-scheme` | — | 兜底 |

## 6. 已知不确定项（需要真实环境确认）

1. 多候选滚动容器（主会话 + 侧栏 embedded 会话）时按「消息行最多」挑选；行数相同且面积接近时判 `ambiguous` 并停止增强。
2. `.md-table-wide` 用 `100cqw` 计算宽度，三列下可能溢出（副本里补了 `container-type: inline-size`）。
3. 宿主 `preserve()` 在 B 期间写 `scrollTop` 的时机（流式/加载历史）未在真实环境观测，可能出现一次抖动。
4. 折叠/展开分组卡片会改变行高：B 用 `ResizeObserver` + 脏消息重测，理论上跟得上，需实测。
