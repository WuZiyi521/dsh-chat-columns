## 十一、0.1.4 复核整改（本轮，两项阻塞）

复核结论：上轮六项与三个独立审查问题均已修复，剩两项阻塞，本轮只做这两项 + 文档口径，
**不重跑完整用例集**。

### B1 根节点全局状态缺少实例所有权保护

- 问题：`apply()` 无条件写 `<html>` 上的 `data-dshc`，disposer 无条件删
  `dshc / dshcWidth / dshcN / dshcState`。热更新时旧实例 disposer 若晚于新实例 apply，
  会把新实例刚写好的版本号、宽度、列数、状态一起抹掉。
- 修复：新增 `<html data-dshcRootOwner>`(`OWNER`)。`apply()` 抢占归属（最新实例获胜）；
  `relayout()`、`cleanupLegacyRootVar()`、disposer 都先过 `ownsRoot()`，
  只有当前属主能写 / 删这组属性。flow 级别的 `data-dshcOwner` 归属保护保持不变。

### B2 findParts() 全局搜 flow、事后才找 scroller

- 问题：一个不属于会话、面积更大的外部 flow（悬浮层 / 注入节点）会赢得面积排序，
  随后 `closest("[data-conversation-scroll]")` 拿到 null，主会话的分栏被整组拆掉。
- 修复：顺序反过来。先用宿主结构认主会话滚动容器——**装着最多 `[data-chat-flow-key]`
  内容行的 `[data-conversation-scroll]`**（行数持平时才用可见面积裁决），
  再只在它内部取 flow 候选；容器外的 flow 不参与。容器内的面积排序、含内容行过滤、
  嵌套 flow 排除、ambiguous 迟滞全部保留。

### 定向回归（本地无头浏览器，`harness/targeted-tests.mjs`）

不依赖真实 DSH：脚本自起静态服务 + 无头 Chrome/Edge，CDP 驱动，跑完自动收尾。
