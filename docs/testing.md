## 二、逐项结果

### T1 列数阈值（真实窗口宽度）

| 滚动容器宽 | 期望 | 实测 |
|---|---|---|
| 1389 | 3 列（每列 ≥420） | 3 ✅ |
| 1289 | 2 列（0.1.0 错算成 3） | 2 ✅ |
| 813 | 1 列 | 1 ✅ |
| 813 + 手动 3 列 | 压回 2 列（硬下限 260） | 2 ✅ |

判定方式：`[data-chat-flow].style.columnCount` + 徽标文案。

### T2 行不被切断 + 列不被顶空（0.1.0 的两个真实缺陷）

第一版修复（全行 `break-inside: avoid`）把**高 1500px 的长消息**也设成整体不劈开，
结果一列填不满、另一列底下空一大片——用户截图直接看到。

实测（同一会话，2 列）：

| 版本 | 列底 | 差值 | 整体高 |
|---|---|---|---|
| 全行 avoid | 2447 / 1537 | **910** | 2447 |
| 只矮卡片 avoid | 2159 / 2083 | **76** | 2159 |

现在的判据（已改正）：
- **矮卡片（≤420px）必须整块不跨列** ✅ 26/182 行被标记为 atomic
- **长消息允许跨列**（报纸读法），跨列行数 > 0 属正常，不算失败
- **列底差 ≤ 列宽的 1/4**（2 列实测 76px、3 列 107px）✅

### T3 缩放与回落

窗口 1700→1100→900→1600 来回切，列数与徽标同步变化；
单列时 `column-count` 清空、`dshc-flow` 类移除、flow 上的变量移除 ✅

### T4 切会话

「墨」→「Administrator」→「墨」：
`[data-chat-flow].dshc-flow` 始终 = 1，无残留；页面无 JS 报错 ✅

### T5 卸载 / 重装（模拟）

从 profile `bundles` 移除插件 → 等 HMR，实测：

```
dshc 标记: 已清 | 徽标: 0 | 样式: 0 | flow 类: false | 变量: 无 | display: flex | 调试 API: undefined
```

全部还原；重新加回后 3 秒内恢复 ✅

### T6 热更不重复

连续 `touch` 插件文件 3 次：徽标 1 个、样式 1 个、调试 API 1 个 ✅

### T7 暗色

给 `body` 加 `data-ds-dark-theme`：徽标底色 `rgb(245,246,247)` → `rgb(53,54,56)`，
文字 `#61666b` → `rgb(207,211,214)`，跟随宿主 ✅

### T8 内容溢出

真实会话中 `pre` 2 个、`table` 1 个，均无横向溢出；滚动容器
`scrollWidth == clientWidth` ✅

### T9 自动加载更早

宿主按钮文案是英文 `Load earlier`，且类名被哈希成 `EvIC1a_older`——
0.1.0 的 `.older button` 选择器**从未命中过**（这是这次最重要的发现）。

0.1.1 用「结构 + 文案」找按钮，并用合成 DOM（与宿主真实结构一致）验证：

| 场景 | 期望 | 实测 |
|---|---|---|
| 用户滚轮 + 滚到顶 | 点一次 | clicks=1 ✅ |
| 只有程序化 `scrollTop=0`（模拟宿主锚点补偿）+ scroll 事件 | 不点 | clicks=0 ✅ |

**未做到**：没有找到 `hasMore = true` 的真实会话，所以「真按钮端到端」没验，
只验到「选择器能命中同构按钮 + 门控正确」。

## 三、修复清单（每条对应一个可复现问题）

| # | 问题 | 证据 | 修复 |
|---|---|---|---|
| F1 | 消息行被列边界切断 | 实测 `rowsSpanningColumns=1`，行 `break-inside=auto` | `break-inside:avoid` 下沉到 `[data-chat-flow-key]/[data-chat-group-key]/[data-chat-turn]` |
| F2 | 自动加载更早从未生效 | 真实 DOM 无 `.older`，按钮在 `EvIC1a_older` | 结构化查找 + 文案匹配 |
| F3 | 列宽低估（忽略 40px 列间距） | 1289px 算出 3 列，每列 403px < 420 | 用 `(W+gap)/(min+gap)` 计算 |
| F4 | 手动列数无视窗口宽度 | 813px 强制 3 列 → 每列约 160px | 硬下限 260px 约束 |
| F5 | 宽度变量写在 `:root`，被宿主局部定义遮蔽 + 影响其它组件 | 宿主在 `.wSkVaW_body` 定义同名变量 | 只写在 flow 自身 |
| F6 | 卸载后 `<html>` 残留 `data-dshc*` | 代码审查 | dispose 时删除 |
| F7 | 切会话后旧 flow 的变量/RO 未释放 | 代码审查 | `lastFlow` + `unobserve` |
| F8 | 徽标 800ms 轮询 + 用错 flow 源 | 代码审查 | 改为 relayout 驱动 + 同一 flow |
| F9 | `api.set(2.5)` 静默回落、存储禁用时点击报错 | 代码审查 | 取整校验 + try/catch |
| F10 | 只有程序化滚动也会触发自动加载 | 设计缺陷 | 3 秒内无用户手势则不点 |

## 四、已知限制（明确标注，未验证的不装懂）

1. **多 flow**：真实页面同时存在 7–11 个 `[data-chat-flow]`（轨迹/子代理面板也带这个属性），
   插件选「滚动容器内第一个有高度的」。当前实测选中的都是主会话；若宿主改变 DOM 顺序，
   可能选错。**未验证**哪种顺序会出问题。
2. **超宽表格**：宿主 `.md-table-wide` 的宽度基于 `100cqw` 和旧的 `--dsh-chat-content-width` 计算，
   三列下可能跨列。真实会话里没遇到宽表，**未验证**。
3. **sticky 元素**（compaction 头、代码块工具条）在多列里的行为，浏览器实现不一致，**未验证**。
4. **hasMore 会话**：本机现有会话都加载完了，自动加载的端到端没跑到。
5. 移动端未适配（任务非目标）。

## 五、未改动（避免为重构而重构）

- 滚动处理里的 DOM 查询：实测 0.029ms/次，不构成问题，不动。
- flow 选择启发式：现状可用，改动风险大于收益，只记录。

## 七、0.1.2 补测（回应「有条件通过」）

上一轮被要求补齐 L-01/L-02（长会话）与 E-01（自动加载端到端）。用一条**真实的 247 行会话**
（历史未加载完，初始只载到第 5 轮）补测：

### E-01 自动加载更早（真实手势）

| | 行数 | 第一轮 | scrollHeight | scrollTop |
|---|---|---|---|---|
| 加载前 | 208 | 5 | 2844 | 2012 |
| 加载后 | 247 | 1 | 4027 | 3195 |

内容增长 1183px，`scrollTop` 也正好 +1183 → **阅读位置零跳动**。
（同一用例在 0.1.1 与 0.1.2 各跑一次，结果一致。）

### L-01 长会话滚动

247 行、3 列：500 次滚动事件共 16.4ms，**0.033ms/次**；无横向溢出。

### L-02 长会话布局与列均衡

| 列数 | 行数 | 整体高 | 各列内容底 | 差 | 占列宽 |
|---|---|---|---|---|---|
| 3 | 247 | 3867 | 3867 / 3867 / 3864 | **3px** | 0.7% |
| 2 | 247 | 5925 | 5925 / 5925 | **0px** | 0% |

缩放 1700→1200→1700 来回，行数不变（247），列数 3→2→3，布局可复现。

### 活动面板选择与安全降级（0.1.2 新增）

注入一个与真实面板等大的 `[data-chat-flow]` 制造"分不清"：

| 场景 | `data-dshc-state` | 行为 |
|---|---|---|
| 只有主会话面板 | `active` | 正常套列 |
| 两个等大面板 | `ambiguous` | **冻结**当前布局，徽标显示「多面板 · 待定」，不猜不拆 |
| 移除干扰后 | `active` | 恢复 |

### 卸载回归（0.1.2）

移除 bundle 后：`data-dshc*` 全清、徽标 0、样式 0、`dshc-flow` 类移除、
内联变量清空、`display` 回到 `flex`、调试 API 消失；重新加回 3 秒内恢复。

## 九、0.1.3 生命周期回归（回应裁决第 1–4 条）
